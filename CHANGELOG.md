# Changelog

## 2026-10-20

[server.py](relay/browser/server.py) provides the PC relay for weather and generic JSON sources. It refreshes a validated snapshot every 900 seconds and serves it through an authenticated loopback endpoint. Tailscale Serve exposes that endpoint through private HTTPS. [data_sources.py](relay/data_sources.py) handles source validation and weather packing, and [binary_protocol.py](relay/binary_protocol.py) supplies XWR encoding and parsing. The notification delivery implementation and its scheduled PC publisher were removed. [main.cpp](project/src/main.cpp) now advertises Nordic UART directly and retains saved Bluetooth bonds, the manual service and the existing watch functions.

[relay_client.js](relay/browser/relay_client.js) runs in the existing Bluefy iPhone browser, writes XWR frames in acknowledged chunks of at most 20 bytes and waits for matching application acknowledgements. [relay_protocol.js](relay/browser/relay_protocol.js) validates framing, CRC, timestamps and fragmented replies. [index.html](relay/browser/index.html) and [style.css](relay/browser/style.css) provide connection and delivery controls. The client checks the PC cache every 30 seconds while visible and again on resume. Hiding the page during delivery cancels that session.

[manage_pc.ps1](relay/browser/manage_pc.ps1) supplies Windows start, stop and status commands for a hidden local server. It records process identity, checks the loopback listener and keeps logs under a private local directory. Live start, status, stop and restart checks passed. Tailscale Serve supplied private HTTPS page access, authenticated weather retrieval returned a validated snapshot, and unauthenticated retrieval returned HTTP 401. The [browser guide](relay/browser/README.md) covers Windows, macOS and Linux, source configuration, foreground delivery and the manual server restart required after a PC reboot.

[relay_client.js](relay/browser/relay_client.js) retains the authorized device after a browser disconnect and restores one previously permitted XIAO Watch after reload through a bounded `getDevices()` lookup when available. Reconnect watch reuses that device; Choose watch requests explicit discovery. A physical connection retained by iOS can therefore remain saved. Before sending data, the client clears unfinished UART input with NUL and LF, sends an unsupported probe with a fresh random sequence and waits for its matching rejection while draining bounded old replies. This preparation leaves watch data unchanged. Stage-specific errors preserve the original failure and redact the access token.

Physical delivery checks before receiver removal confirmed a 192-byte weather frame with server and watch sequence `1792543636`, 24 hourly forecasts, seven daily summaries and a trusted RTC. The next scheduled PC snapshot, sequence `1792544537`, reached the watch as relay revision 2. A later page reload and Disconnect/Reconnect both passed with the saved iPhone pairing intact; the watch accepted sequence `1792545436` as revision 3. These checks establish individual deliveries and reconnections, not prolonged cadence or locked-phone operation.

The existing UART parser passed 14,564 native framing and synchronization assertions. JavaScript checks covered retained-link reconnection, saved-device lookup, duplicate acknowledgements, stale replies, cancellation, stream limits, suspended timers and delayed native writes. Python/JavaScript protocol checks passed 864 assertions. After transport removal, 35,337 Python compatibility and backend checks passed, including malformed inputs, daylight-saving forecasts, snapshot expiry, authentication and unchanged XWR bytes. A fresh Open-Meteo fetch produced a 192-byte weather body. The firmware built with the retired receiver absent from its linked symbols. These build and simulated checks remain separate from physical verification.

The integrated firmware uploaded through PlatformIO with a freshly fetched weather fallback. [sync_rtc.py](project/tools/sync_rtc.py) verified the PCF8563 after provisioning UTC. The upload build used 100,964 bytes of static RAM and 649,612 bytes of application flash; those figures do not measure peak runtime allocation. The PC server restarted with its current source modules, returned HTTP 401 without authorization and returned a validated 192-byte weather body with authorization. The obsolete Windows publishing task was removed after its exact action and owner were checked. A subsequent Bluefy reconnection with the saved iPhone pairing confirmed weather acceptance on the uploaded firmware. USB diagnostics matched the PC snapshot sequence `1792546424`, reported relay revision 1 with `embedded=0`, and retained 24 hourly forecasts and seven daily summaries. The RTC remained trusted, and sensor and display error counters remained zero.

[manage_pc.ps1](relay/browser/manage_pc.ps1) treats a recorded process with a different creation time as stopped, allowing recovery when Windows reuses its PID after a reboot. It checks the full process identity when creation times match and preserves the existing port and duplicate-instance checks. Thirty simulated Start, Status and Stop scenarios passed 82 assertions, including PID reuse, malformed records, occupied ports and a stop-time process race. No unrelated process was started or stopped during those checks.

## 2026-10-19

The relay gained the project-owned XWR v1 binary protocol, with Python encoding and parsing in [binary_protocol.py](relay/binary_protocol.py) and C++ parsing in [binary_protocol.cpp](project/src/binary_protocol.cpp), declared in [binary_protocol.h](project/include/binary_protocol.h). Packets carry an explicit version, payload codec, sequence, topic, lengths and CRC32. Typed generic values include integers, finite floating-point numbers, UTF-8 text, collections and opaque bytes. The C++ parser validates generic values without allocating a JSON document, and [watch_model.h](project/include/watch_model.h) retains their encoding alongside the cached bytes. [packed_weather.cpp](project/src/packed_weather.cpp) retains the existing 118-byte weather representation and feeds its semantic checks in [phone_protocol.cpp](project/src/phone_protocol.cpp).

XWR weather packing reduced the complete text body to 192 bytes while retaining current conditions, 24 hourly forecasts and seven daily summaries. The packet contains 118 weather bytes and remains within the 189-byte raw and 256-byte text bounds. [main.cpp](project/src/main.cpp) feeds Nordic UART bytes to `LineFramer` in [phone_protocol.cpp](project/src/phone_protocol.cpp), which assembles LF-terminated frames. Acknowledgements and refresh polls remain JSON. [relay/PROTOCOL.md](relay/PROTOCOL.md) defines packet layouts, parser APIs and rejection behavior.

Validation passed 40,041 native assertions and a PlatformIO upload. Checks covered encoder/parser agreement, malformed input, allocation failures, unchanged state after rejection, sequence ordering, JSON compatibility and weather across daylight-saving transitions. [platformio_weather.py](project/tools/platformio_weather.py) called [upload_weather.py](project/tools/upload_weather.py) to refresh the embedded forecast, and [platformio_rtc.py](project/tools/platformio_rtc.py) called [sync_rtc.py](project/tools/sync_rtc.py) to set and verify RTC UTC. USB diagnostics confirmed decoder support and advancing watch-task progress without touch, sensor or display errors. One binary weather transfer through the then-active iPhone route matched sequence `1792456927`, retained both forecast sets and left the RTC trusted; no new screen or phone lock-state confirmation was recorded.

## 2026-10-16

The compact weather representation retained the complete current, 24-hour and seven-day data in 118 bytes. [packed_weather.cpp](project/src/packed_weather.cpp) preserves temperature tenths, WMO codes, local-day durations and daylight-saving metadata, rejects invalid encodings and passes decoded fields to [phone_protocol.cpp](project/src/phone_protocol.cpp) for validation before application. Complete forecast delivery through the iPhone was verified during this revision. The upload-time fallback and separate Nordic UART transport remained available.

[watch_ui.cpp](project/src/watch_ui.cpp) removed the Weather application's current-conditions and snapshot-source header blocks. Both forecast tabs now show only the fetch timestamp as `Updated MM/DD/YY HH:MM:SS`, with a placeholder when that timestamp is absent. The face complication, hourly forecasts, daily summaries, scrolling and return navigation remain in place.

Shared button and forecast-tab styling in [watch_ui.cpp](project/src/watch_ui.cpp) reduced repeated UI setup. Dial updates reuse the local-date conversion for hands and date text, while calendar arithmetic in [watch_model.cpp](project/src/watch_model.cpp) uses a shared validated 32-bit conversion body. Weather normalization in [upload_weather.py](project/tools/upload_weather.py) now uses binary searches over validated timestamps to locate hourly and daily ranges.

## 2026-10-15

[phone_protocol.cpp](project/src/phone_protocol.cpp) introduced versioned JSON topic envelopes, application acknowledgements, bounded framing and sequence tracking for eight topics, using [strict_json.cpp](project/src/strict_json.cpp) for strict validation. Unknown topics use the latest-payload cache declared in [watch_model.h](project/include/watch_model.h), while `readRelayWeather()` replaces the current conditions and both forecast sets together. [relay_schedule.h](project/include/relay_schedule.h) sets the Nordic UART refresh interval to 900 seconds, with polling handled in [main.cpp](project/src/main.cpp).

The source-comment convention changed to concise lowercase prose, preserving proper names, acronyms, exact identifiers and units. Comments describe functions, APIs, scopes, branches, loops, callbacks and meaningful setup groups, using native syntax for each language. The standalone [sync_rtc.py](project/tools/sync_rtc.py) helper also provisioned the hardware RTC without a firmware or weather change.

## 2026-10-06

The PCF8563 became the primary clock. [main.cpp](project/src/main.cpp) schedules reads through [board_support.cpp](project/src/board_support.cpp) at boot and once per second, while [watch_model.cpp](project/src/watch_model.cpp) interpolates between readings and recovers trust after transient read failures. The post-upload hook [platformio_rtc.py](project/tools/platformio_rtc.py) invokes [sync_rtc.py](project/tools/sync_rtc.py) to write fresh computer UTC and verify both readback and ticking. [rtc_usb_protocol.cpp](project/src/rtc_usb_protocol.cpp) parses those USB requests for the watch task. Bluetooth time-setting support was removed from [manual_protocol.cpp](project/src/manual_protocol.cpp), [phone_protocol.cpp](project/src/phone_protocol.cpp) and their runtime handling in `main.cpp`. Reboot no longer depends on a phone time message or a compilation timestamp.

[watch_ui.cpp](project/src/watch_ui.cpp) reduced the face's weather and battery visuals and moved them outward toward the minute marks. The weather artwork now occupies 60 by 44 pixels with a larger unscaled touch target, and the battery body occupies 32 by 18 pixels above the center. Battery text uses font 10; temperature uses font 12 with a font-10 fallback and optional degree omission when necessary to retain the whole value.

Single-axis orientation wake added the LSM6DS3TR-C Z driver in [orientation_sensor.cpp](project/src/orientation_sensor.cpp), with filtering and hold times in [orientation_wake.cpp](project/src/orientation_wake.cpp) and recovery in [main.cpp](project/src/main.cpp). Sensor power initialization in `orientation_sensor.cpp` changed to H0H1 high drive after the internal bus failed to respond with standard drive. The dim view in [watch_ui.cpp](project/src/watch_ui.cpp) uses a black face, white marks and hour/minute hands, and the existing red second hand. Complications and controls disappear, and touch cannot wake or navigate until orientation restores the normal face.

[backlight.cpp](project/src/backlight.cpp) added hardware PWM on D6, using the duties selected in `main.cpp`: 10/255 when dim and 255/255 when awake. [display_transport.cpp](project/src/display_transport.cpp) changed the display path to one blocking TX-only SPI transfer per RGB565 strip at 8 MHz while retaining the 4,800-byte draw buffer. The settings in [orientation_wake.h](project/include/orientation_wake.h) were shortened to a 30 ms filter, 40 ms wake hold and 80 ms dim hold, then tightened from the initial 45°/55° range to approximately 35°/45°. Both KE switches remain on for battery measurement and backlight control.

## 2026-10-03

Weather became an upload-time fallback. [project/platformio.ini](project/platformio.ini) registers [platformio_weather.py](project/tools/platformio_weather.py) as a pre-build hook. That script calls `prepare()` in [upload_weather.py](project/tools/upload_weather.py) to fetch Open-Meteo data for ZIP 10018, validate it and generate `project/.pio/build/seeed_xiao_nrf52840_sense/generated/upload_weather_data.h` with 24 hourly forecasts and seven daily summaries. The `normalize()` function selects daily icons from the most frequent hourly icon group, with first occurrence resolving ties. Plain builds retain the dated `project/.pio/weather/last_upload.json` cache or an unavailable snapshot, while uploads require fresh data.

The analog clock in [watch_ui.cpp](project/src/watch_ui.cpp) expanded to the round face and adopted a white background, black primary text, red secondary text, black marks and hour/minute hands, and a red second hand. Hour numerals were removed. The battery percentage moved inside its symbol above the center, temperature moved inside the weather symbol to the left, and the date moved below the center. The scrolling launcher in `watch_ui.cpp` gained smaller rows and a fixed return arrow, while [calendar_ui.cpp](project/src/calendar_ui.cpp) added the month-browsable 2026 Calendar.

Date and weather shortcuts in `watch_ui.cpp` gained pressed feedback and direct application navigation. The date separator changed from literal slashes to a line break. A glass-style date container was introduced and subsequently removed, leaving only the date text. Red shortcut outlines gave way to a slight ease-out shrink, and navigation moved to first contact to avoid requiring a second tap. Hit targets remain unscaled, and held contacts cannot activate the following screen. The weather and battery symbols in `watch_ui.cpp` received size and placement adjustments.
