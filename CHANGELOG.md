# Changelog

## 2026-10-19

The relay gained the project-owned XWR v1 binary protocol, with Python encoding and parsing in [binary_protocol.py](relay/publisher/binary_protocol.py) and C++ parsing in [binary_protocol.cpp](project/src/binary_protocol.cpp), declared in [binary_protocol.h](project/include/binary_protocol.h). Packets carry an explicit version, payload codec, sequence, topic, lengths and CRC32. Typed generic values include integers, finite floating-point numbers, UTF-8 text, collections and opaque bytes. The C++ parser validates generic values without allocating a JSON document, and [watch_model.h](project/include/watch_model.h) retains their encoding alongside the cached bytes. [packed_weather.cpp](project/src/packed_weather.cpp) retains the existing 118-byte weather representation and feeds its semantic checks in [phone_protocol.cpp](project/src/phone_protocol.cpp).

[publisher.py](relay/publisher/publisher.py) now uses `binary_protocol.py` to wrap binary packets in Base64 for ntfy and ANCS. A complete weather notification occupies 192 bytes instead of the previous 240-byte JSON envelope, preserving current conditions, 24 hourly forecasts and seven daily summaries. The complete body remains capped at 256 bytes; the separate 256 KiB source-download bound does not increase notification capacity. Legacy JSON reception and the `--wire-format json` publisher option remain available. [main.cpp](project/src/main.cpp) feeds NUS bytes to `LineFramer` in `phone_protocol.cpp`, which assembles newline-terminated frames for parsing; acknowledgements and polls remain JSON. [relay/PROTOCOL.md](relay/PROTOCOL.md) documents packet layouts, parser APIs, limits and rejection behavior.

Validation passed 40,041 native assertions, checks of `binary_protocol.py` and `publisher.py`, and a PlatformIO upload. Tests covered encoder/parser agreement, malformed inputs, allocation failures, unchanged state after rejection, sequence ordering, legacy compatibility and weather across daylight-saving transitions. The upload refreshed the embedded forecast through [platformio_weather.py](project/tools/platformio_weather.py) and [upload_weather.py](project/tools/upload_weather.py), then set and verified the RTC through [platformio_rtc.py](project/tools/platformio_rtc.py) and [sync_rtc.py](project/tools/sync_rtc.py). USB status from `main.cpp` confirmed binary decoder support and advancing watch-task progress without touch, sensor or display errors. The Windows launcher [run_pc.ps1](relay/publisher/run_pc.ps1) switched to binary after firmware verification.

A 192-byte XWR weather notification reached the watch through the iPhone after reconnection. Publisher and watch reports matched sequence `1792456927` and fingerprint `F0A302BE`. The watch accepted one update without ANCS errors, drops or rejections, replaced the embedded snapshot, and retained 24 hourly forecasts and seven daily summaries. The RTC remained trusted. This check established binary delivery and application acceptance; no separate screen or phone lock-state confirmation was recorded, and sustained cadence remains unverified.

The maintained guides now cover the default binary transport, parser use, packet and notification limits, legacy compatibility, and the distinction between structural parsing and watch-side acceptance. Setup and diagnostics separate source JSON, XWR packets, Base64 notification text and LightBlue commands. The protocol examples and implementation diagrams describe the current paths, while delivery notes distinguish the binary test from the earlier locked-phone tests. These documentation changes leave firmware, publisher settings and device state unchanged.

It covers Windows, macOS and Linux workflows and identifies the driver, Bluetooth, memory and USB changes needed for another board. [project/README.md](project/README.md), [project/LIGHTBLUE.md](project/LIGHTBLUE.md), [relay/README.md](relay/README.md) and [relay/publisher/README.md](relay/publisher/README.md) distinguish current behavior from untested adaptations. ## 2026-10-16

The notification relay moved to the existing ntfy iPhone app and Apple ANCS, with [publisher.py](relay/publisher/publisher.py) fetching weather and generic HTTPS JSON and [notification_relay.cpp](project/src/notification_relay.cpp) receiving matching notifications. [schedule_pc.ps1](relay/publisher/schedule_pc.ps1) added 15-minute execution, login and missed-run recovery, hidden execution, overlap prevention and a two-minute deadline for [run_pc.ps1](relay/publisher/run_pc.ps1). Setup instructions in [relay/README.md](relay/README.md) distinguish Notification Center alerts from Lock Screen alerts and require accessible previews and system-notification sharing. The custom iPhone application and its build files were removed after the relay approach changed.

Phone delivery checks exposed truncation of longer notification bodies at 256 bytes on the tested path. `publisher.py` limits complete envelopes to that size. Its `pack_weather()` adapter packs the complete current, 24-hour and seven-day data into 118 binary bytes represented by 160 Base64 characters. [packed_weather.cpp](project/src/packed_weather.cpp) retains temperature tenths, WMO codes, local-day durations and daylight-saving metadata, rejects invalid encodings and passes decoded data to [phone_protocol.cpp](project/src/phone_protocol.cpp) for validation before application. This adapter leaves other JSON topics generic.

[notification_relay.cpp](project/src/notification_relay.cpp) gained ANCS pairing, subscription, metadata, body-length and fingerprint diagnostics. Task synchronization around immediate SoftDevice calls replaced an interrupt-priority masking approach that interfered with runtime progress. [notification_frame.cpp](project/src/notification_frame.cpp) and [notification_protocol.cpp](project/src/notification_protocol.cpp) handle notification assembly, filtering and acceptance, while `packed_weather.cpp` decodes compact weather. These changes preserved the separate Nordic UART diagnostic transport in `main.cpp` and the upload weather fallback.

[watch_ui.cpp](project/src/watch_ui.cpp) removed the Weather application's current-conditions and snapshot-source header blocks. Both forecast tabs now show only the fetch timestamp as `Updated MM/DD/YY HH:MM:SS`, with a placeholder when that timestamp is absent. The face complication, hourly forecasts, daily summaries, scrolling and return navigation remain in place.

Shared button and forecast-tab styling in [watch_ui.cpp](project/src/watch_ui.cpp) reduced repeated UI setup. Dial updates reuse the local-date conversion for hands and date text, while calendar arithmetic in [watch_model.cpp](project/src/watch_model.cpp) uses a shared validated 32-bit conversion body. Weather normalization in [upload_weather.py](project/tools/upload_weather.py) now uses binary searches over validated timestamps to locate hourly and daily ranges. An explored rewrite of [packed_weather.cpp](project/src/packed_weather.cpp) was discarded, leaving its decoder implementation in place.

## 2026-10-15

[phone_protocol.cpp](project/src/phone_protocol.cpp) introduced versioned JSON topic envelopes, application acknowledgements, bounded framing and sequence tracking for eight topics, using [strict_json.cpp](project/src/strict_json.cpp) for strict validation. Unknown topics use the latest-payload cache declared in [watch_model.h](project/include/watch_model.h), while `readRelayWeather()` replaces the current conditions and both forecast sets together. [relay_schedule.h](project/include/relay_schedule.h) sets the optional Nordic UART refresh interval to 900 seconds, with polling handled in [main.cpp](project/src/main.cpp). The initial custom companion implementation belonged to this revision; it was subsequently removed.

The source-comment convention changed to concise lowercase prose, preserving proper names, acronyms, exact identifiers and units. Block comments were added before functions, APIs, scopes, branches, loops, callbacks and meaningful setup groups, using native syntax for each language. The standalone [sync_rtc.py](project/tools/sync_rtc.py) helper also provisioned the hardware RTC without a firmware or weather change.

## 2026-10-07

A normal PlatformIO upload ran [platformio_weather.py](project/tools/platformio_weather.py) and [upload_weather.py](project/tools/upload_weather.py) to refresh the embedded forecast, then [platformio_rtc.py](project/tools/platformio_rtc.py) and [sync_rtc.py](project/tools/sync_rtc.py) to provision the RTC from computer UTC. The upload retained the existing interface, 24-hour forecasts, seven-day summaries and orientation policy. No application feature changed in this session.

## 2026-10-06

The PCF8563 became the primary clock. [main.cpp](project/src/main.cpp) schedules reads through [board_support.cpp](project/src/board_support.cpp) at boot and once per second, while [watch_model.cpp](project/src/watch_model.cpp) interpolates between readings and recovers trust after transient read failures. The post-upload hook [platformio_rtc.py](project/tools/platformio_rtc.py) invokes [sync_rtc.py](project/tools/sync_rtc.py) to write fresh computer UTC and verify both readback and ticking. [rtc_usb_protocol.cpp](project/src/rtc_usb_protocol.cpp) parses those USB requests for the watch task. Bluetooth time-setting support was removed from [manual_protocol.cpp](project/src/manual_protocol.cpp), [phone_protocol.cpp](project/src/phone_protocol.cpp) and their runtime handling in `main.cpp`. Reboot no longer depends on a phone time message or a compilation timestamp.

[watch_ui.cpp](project/src/watch_ui.cpp) reduced the face's weather and battery visuals and moved them outward toward the minute marks. The weather artwork now occupies 60 by 44 pixels with a larger unscaled touch target, and the battery body occupies 32 by 18 pixels above the center. Battery text uses font 10; temperature uses font 12 with a font-10 fallback and optional degree omission when necessary to retain the whole value.

Single-axis orientation wake added the LSM6DS3TR-C Z driver in [orientation_sensor.cpp](project/src/orientation_sensor.cpp), with filtering and hold times in [orientation_wake.cpp](project/src/orientation_wake.cpp) and recovery in [main.cpp](project/src/main.cpp). Sensor power initialization in `orientation_sensor.cpp` changed to H0H1 high drive after the internal bus failed to respond with standard drive. The dim view in [watch_ui.cpp](project/src/watch_ui.cpp) uses a black face, white marks and hour/minute hands, and the existing red second hand. Complications and controls disappear, and touch cannot wake or navigate until orientation restores the normal face.

[backlight.cpp](project/src/backlight.cpp) added hardware PWM on D6, using the duties selected in `main.cpp`: 10/255 when dim and 255/255 when awake. [display_transport.cpp](project/src/display_transport.cpp) changed the display path to one blocking TX-only SPI transfer per RGB565 strip at 8 MHz while retaining the 4,800-byte draw buffer. The settings in [orientation_wake.h](project/include/orientation_wake.h) were shortened to a 30 ms filter, 40 ms wake hold and 80 ms dim hold, then tightened from the initial 45°/55° range to approximately 35°/45°. Both KE switches remain on for battery measurement and backlight control.

## 2026-10-03

Weather became an upload-time fallback. [project/platformio.ini](project/platformio.ini) registers [platformio_weather.py](project/tools/platformio_weather.py) as a pre-build hook. That script calls `prepare()` in [upload_weather.py](project/tools/upload_weather.py) to fetch Open-Meteo data for ZIP 10018, validate it and generate `project/.pio/build/seeed_xiao_nrf52840_sense/generated/upload_weather_data.h` with 24 hourly forecasts and seven daily summaries. The `normalize()` function selects daily icons from the most frequent hourly icon group, with first occurrence resolving ties. Plain builds retain the dated `project/.pio/weather/last_upload.json` cache or an unavailable snapshot, while uploads require fresh data. The prior continuous server/MQTT approach was retired and its server directory removed.

The analog clock in [watch_ui.cpp](project/src/watch_ui.cpp) expanded to the round face and adopted a white background, black primary text, red secondary text, black marks and hour/minute hands, and a red second hand. Hour numerals were removed. The battery percentage moved inside its symbol above the center, temperature moved inside the weather symbol to the left, and the date moved below the center. The scrolling launcher in `watch_ui.cpp` gained smaller rows and a fixed return arrow, while [calendar_ui.cpp](project/src/calendar_ui.cpp) added the month-browsable 2026 Calendar.

Date and weather shortcuts in `watch_ui.cpp` gained pressed feedback and direct application navigation. The date separator changed from literal slashes to a line break. A glass-style date container was introduced and subsequently removed, leaving only the date text. Red shortcut outlines gave way to a slight ease-out shrink, and navigation moved to first contact to avoid requiring a second tap. Hit targets remain unscaled, and held contacts cannot activate the following screen. Weather and battery artwork received additional size and placement adjustments during the same session.

## 2026-10-02

The initial interface in [watch_ui.cpp](project/src/watch_ui.cpp), driven by [main.cpp](project/src/main.cpp), added an analog face, a single-tap launcher, a time-only Clock view and a Weather view. [platformio.ini](project/platformio.ini) combined Seeed_GFX, Seeed_Arduino_RoundDisplay, LVGL, ArduinoJson and RTClib with framework Bluetooth and USB support. The application's current timestamp rules, theme, forecast coverage and RTC ownership were refined in the dated revisions above.

A blank-screen investigation replaced the vendor flush path in `lv_xiao_round_screen.h`, which waited on SPIM0 while the display used SPIM3. The replacement callback and USB status reporting in [main.cpp](project/src/main.cpp) exposed startup stages and watch-task progress while retaining vendor initialization and synchronous drawing. The October 6 revision later moved bulk strip transfers into [display_transport.cpp](project/src/display_transport.cpp).

Application return controls in [watch_ui.cpp](project/src/watch_ui.cpp) changed from the `Apps` and `Face` text buttons to larger arrows. Release handling replaced the short-click-only condition so longer presses could return. A subsequent launcher freeze led to bounded TWIM0 touch reception, static DMA storage, bus recovery and stale-event clearing in [board_support.cpp](project/src/board_support.cpp). Explicit layout completion in `watch_ui.cpp` corrected a separate first-return miss after navigation.

[manual_bluetooth.cpp](project/src/manual_bluetooth.cpp) and [manual_protocol.cpp](project/src/manual_protocol.cpp) added the LightBlue service and short ASCII commands for diagnostics, units, time with a display offset, current weather and staged hourly forecasts. `manual_bluetooth.cpp` used bounded callback queues and readable results. Its explicit descriptor setup was replaced with the core's supported user-description mechanism after initialization failed. Later revisions removed Bluetooth clock setting while retaining these diagnostic and weather paths.
